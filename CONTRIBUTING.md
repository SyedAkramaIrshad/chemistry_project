# Contributing to ChemLab Studio

Thank you for helping build an open chemistry learning environment.

## Start locally

```bash
npm install
npm run dev
```

Before sharing a change, create the production bundle:

```bash
npm run build
```

## Non-negotiable interaction rules

1. A learner action may change only the atom, bond, charge, condition, or parameter they explicitly selected.
2. Rejected actions must leave the scientific state unchanged.
3. Never silently add hydrogen, remove a leaving group, alter another bond, repair charge, or choose a reaction product.
4. Preserve open and incomplete states so learners can inspect them.
5. Distinguish a graph-valid edit from a stable species, favorable pathway, or real experimental outcome.
6. State when solvent, temperature, pressure, concentration, phase, catalyst, light, kinetics, or another missing condition prevents a unique answer.

## Adding chemistry coverage

Every scientific contribution should identify which category it belongs to:

- deterministic law or conservation rule;
- approximate model with assumptions;
- empirical rule with a stated domain;
- measured value with source and conditions;
- numerical or quantum calculation with method and parameters.

Do not encode a measured trend or textbook shortcut as a universal law.

## Adding a curriculum topic

Curriculum metadata lives in `src/data/curriculum.js`. A new topic must include:

- a learner-facing name;
- one short explanation;
- an availability state: `live`, `concept`, or `next-engine`;
- a model-boundary statement when the interface could otherwise overclaim.

Only use `live` when a working interaction exists in the repository.

## Interface expectations

- Make the next learner action visible without relying on a hidden gesture.
- Explain errors in plain language and name the relevant chemical reason.
- Keep keyboard focus visible.
- Preserve usability at narrow/mobile and desktop widths.
- Respect reduced-motion preferences.
- Use the experiment trace for meaningful state changes rather than decorative notifications.

## Review journeys

For molecular graph interaction changes, complete these browser journeys:

1. Load the guided bond-rewrite challenge.
2. Select an O-H bond and break it.
3. Confirm N, O, H, and H all remain while the bond count decreases.
4. Form an N-O single bond.
5. Confirm the result remains open and no other graph edit occurred.
6. Attempt a blocked bond such as N-He and confirm the graph is unchanged while the reason is recorded.

For Molecular Interaction Observatory changes, run `npm run verify:intermolecular` and exercise both persistent modes in the browser. In HCl/HCl, keep the default misalignment, select the declared δ+ and δ− ports, choose dipole–dipole, and confirm the rejected attempt preserves both sites and both angles while naming the angular gate. Load its alignment reference and confirm no bridge appears until the explicit Attempt action. Rotate a committed bridge outside tolerance and verify it remains visible as strained until the learner presses Break. In water/water and water/acetone, submit incomplete family sets and confirm each multi-family answer stays selected while London dispersion, permanent dipole–dipole, and the declared hydrogen-bond contact are compared independently from orientation and covalent change. In methane/methane, confirm the cloud contact has no preferred orientation in this model. In Na⁺/water and Cl⁻/water, verify the favored water end reverses with ion sign without changing an O–H bond. In both symbolic shells, toggle one water at a time, preserve the other five, check a deliberately wrong favored end and raw count, and confirm the reference count of six is labelled an interface target rather than a hydration number. Check all six pair scenarios, both shells, four hints per mode, teacher prompts, every source, and every passport inclusion/exclusion. At 390, 742, and desktop widths verify More-menu navigation, hash alignment, persistent inactive-mode state, 44-pixel controls, semantic SVG site keyboard activation, visible focus, internal scenario scrolling, no clipped rotors or shell, no body overflow, reduced motion, and no runtime errors. Never present the observatory as universal force detection, experimental hydrogen-bond proof, energy or strength ranking, optimized or measured structure, hydration number, solubility or bulk-property prediction, reaction, or biological effect.

For curriculum or copy changes, inspect at least one live discipline and one discipline that requires another engine. The distinction must remain obvious.

Compare Be/B and N/O first-ionization records and state the broad pattern without turning it into a monotonic law. ## Safety

Do not contribute operational hazardous synthesis instructions, unsupervised laboratory procedures, or claims that the software replaces professional safety review.
